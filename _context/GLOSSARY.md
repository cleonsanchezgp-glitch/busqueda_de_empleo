| Term | Definition |
| --- | --- |
| Accepted offer | A collected job offer that satisfies the configured search profile closely enough to be stored for notification or analysis. |
| Application destination | The website or portal where the candidate ultimately applies, which may differ from the source portal where the offer was discovered. |
| Collection cycle | One execution of the collection workflow across the configured supported portals. |
| Collection scheduler | The system component that starts manual or recurring collection cycles and records their status. |
| Connector adapter | A portal-specific integration behind the common connector contract, such as LinkedIn, InfoJobs, or Tecnoempleo. |
| Filter reasoning | Stored metadata explaining why an offer was accepted, rejected, or marked for manual review. |
| GitHub Project 3 | The declared Planning and Time authority for this repository, hosted at `https://github.com/users/cleonsanchezgp-glitch/projects/3`. |
| Job offer | A vacancy or employment opportunity collected from a supported job portal or reachable application destination. |
| Job seeker | The primary user who receives relevant software developer job offers and reviews statistics. |
| Manual review | The state used when an offer cannot be confidently accepted or rejected from available signals. |
| Notification candidate | A newly accepted offer prepared for WhatsApp delivery before provider success or failure is known. |
| Portal connector | A component that retrieves offer data from a supported job portal through a permitted access method. |
| Qualitas | The documentation and QA practice used in this repository to connect Specification, Design, Planning, Time, Verification, and Traceability. |
| Search profile | The configured criteria for suitable offers: junior or up to approximately 2 to 3 years of experience, software developer role, on-site modality, and Zaragoza location. |
| Source portal | The portal where the system first discovered the job offer, such as LinkedIn, InfoJobs, or Tecnoempleo. |
| Statistics dashboard | The frontend view that displays source portal and application destination statistics from the backend API. |
| Traceability Matrix | A derived projection linking objectives, requirements, architecture decisions, GitHub planning items, planned tests, evidence, and status. |
| Unknown destination | A first-class application destination value used when the system cannot confirm where the candidate must apply. |
| WhatsApp messaging provider | The approved external provider or adapter used to deliver job-offer notifications to the user's personal phone. |
| Work Package | A GitHub planning issue with `WP-xxx` identity that groups delivery work realizing one or more functional or non-functional requirements. |
